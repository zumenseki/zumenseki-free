# 研究 — 検索が最速になる知識ベース構造

## 結論（一言）
**単一の万能構造は存在しない。「具体的事実→キーワード/ベクトル、横断・多段→階層要約/グラフ」とルーティングするのが最適。** 構造化インデックスの主効果は精度より「速度（トークン・レイテンシ削減）」。

## 主要な根拠

### 1. ルーティングが正解（複数論文が収束）
- GraphRAGは大域sensemakingでベクトルRAGに勝率70-80%だが、独立ベンチでは「実タスクで素のRAGに頻繁に負ける」。単一ホップ事実はベクトル/BM25が同等以上で安い。
  - Microsoft GraphRAG blog / arXiv 2404.16130
  - 2502.11371（RAG vs GraphRAG 系統評価：相補的、片方が常勝ではない）
  - 2506.05690（When to use Graphs in RAG：素RAGに頻繁に負ける）

### 2. キーワード(BM25)は堅牢 — エージェントのgrepはここで最強
- BEIR 18データセットで最良の密ベクトルでもBM25超えは8/18のみ。固有名詞・レア語・ドメイン外で強い。
  - arXiv 2104.08663（BEIR）/ 2407.07790（Touché-2020でBM25が依然優位）
- → ファイルVaultでエージェントが行うgrep＝キーワード検索は、研究上「最も堅牢な検索」と一致。

### 3. ハイブリッド + RRF が最良だが利得はデータ依存
- BM25+密ベクトルをRRF（`1/(k+rank)`, k=60）で融合すると単体超え。ただしSciFact +1.2%、NFCorpus改善なし。
  - Cormack SIGIR'09（RRF）
- cross-encoderリランカは+5〜15 nDCG だがO(N)で遅い（~100-200ms/30件）。

### 4. HNSW = 対数時間
- 確率的スキップリスト類似で O(log n)、ANNでPareto最適。※ファイルVaultにベクトルDBは無いので直接は使わない。
  - arXiv 1603.09320

### 5. RAPTOR（階層要約ツリー）が最も示唆的
- 再帰クラスタリング+LLM要約でツリー化。QuALITY +20pt（82.6%）。
- **collapsed-tree（要約＋葉を一面に並べて検索）が層別走査に勝つ**＝質問ごとに適切な粒度を選べる。
- 高階層要約は横断・多段質問に必須。構築コストは文書長に線形。
  - arXiv 2401.18059
- ⚠️「要約を先読み→必要時だけ葉」省トークン戦略は論文に直接の実証なし（仮説）。

### 6. エージェント長期記憶 — 構造化は"効率"を買う
- MemGPT：コンテキストをOS仮想メモリに見立て main↔external をページング（arXiv 2310.08560）。
- Generative Agents：記憶ストリームを recency(0.995減衰)+importance(1-10)+relevance(コサイン) の加重和で検索、重要度合計150でreflection（DOI 3586183.3606763）。
- A-MEM：記憶を「内容+キーワード+タグ+文脈説明+リンク」のZettelkasten型に構造化し進化（arXiv 2502.12110）。
- Mem0：構造化メモリでトークン~90%減・p95レイテンシ91%減・精度約6pt減＝主効果は効率（arXiv 2504.19413）。
- CoALA：semantic/episodic/procedural の型付き記憶（arXiv 2309.02427）。

### 7. PKM/findabilityの人間研究
- フォルダは浅く小さければ速い（平均深さ2.86・11ファイル/フォルダ・94%を~15秒で発見、TAU 101.pdf）。
- 個人ファイルではナビゲーション(56-68%)が検索(4-15%)を圧倒（同）。
- 手の込んだフォルダ/タグ整備は再発見を確実には改善しない（ACM 1979457 / Wiley asi.22906）。
- frontmatter `description` で本文を読まず関連判定＝progressive disclosure（Claude Codeのskill読込が実例）。
- 原子ノート・MOCは実証でなく実務原則（Matuschak / LYT）。

## 本Vaultへの適用（このリポで実装済み）
1. `00_INDEX/INDEX.md` を `_tools/build-index.mjs` で自動生成＝手製の転置インデックス/collapsed-tree最上層。
2. frontmatterに `aliases`/`keywords`＝キーワード検索の的（BM25堅牢性）。
3. AGENTS.md を2経路ルーティングに改訂（事実→INDEXキーワード検索→葉／横断→MOC要約）。
4. フォルダ最大3階層（PKM実証）。

## 信頼度の注意
多くの学術ドメインが直接フェッチを拒否（403）したため、主張は検索スニペット（論文引用）ベース。
複数ソースで一致した数値（QuALITY 82.6%、BEIR 8/18、RRF k=60、減衰0.995）は高信頼、単一ブログ由来のレイテンシは桁の目安。
