# AGENTS.md — この知識ベース（脳）の歩き方

このフォルダ `brain-vault/` は所有者の「第二の脳」です。Obsidian で人間が閲覧・編集し、
Codex / Claude Code などのコーディングエージェントが**共有メモリ**として読み書きします。
複数プロジェクト（入札エージェント / ズメンセキ 等）の構想・仕様・決定を蓄積します。

容量は無限に増える前提です。だから **全文走査は禁止**。「地図 → 必要な1枚」だけ取りに行きます。

---

## 必須ナビゲーション手順（コンテキスト節約のため厳守）

1. まず `00_INDEX/HOME.md` だけを読む。
2. タスクに該当する `00_INDEX/MOC_*.md`（地図）を **1枚だけ** 読む。
3. MOC内のリンクから、**本当に必要な原子ノートだけ** を開く。
4. 各ノート冒頭の `> 要約:` 行で要否を判断してから本文を読む。
5. `20_Notes/` の一括読み込み・Vault全体の grep / glob は **しない**。
   検索が必要なら MOC を経由する（MOC に載っていないものは「まだ存在しない」と判断してよい）。

> なぜ: ノートが何万枚に育っても、1タスクで読むのは数枚（数KB）に収まる。これが
> 「無限容量 × 最小コンテキスト」を両立させる唯一の仕組み。

---

## 書き込みルール

- **1ノート = 1概念**。長くなったら分割し、リンク `[[ノート名]]` で繋ぐ。
- 新規ノートは必ずテンプレ（`_templates/` 参照）に従い、frontmatter と `> 要約:` 3行を付ける。
- 作業の結論・判断は、該当プロジェクトの `決定ログ.md` に **追記**する（既存行は消さない）。
- 新しい原子ノートを作ったら、対応する `00_INDEX/MOC_*.md` に**リンクを1行追記**する
  （MOC に載らないノートは他のエージェントから見えない＝存在しないのと同じ）。
- 不要になったノートは削除せず `90_Archive/` へ移動する。

---

## frontmatter 規約（全ノート共通）

```yaml
---
type: project        # project | concept | log | resource | moc
project: ズメンセキ   # 関連プロジェクト名（無ければ省略可）
status: active        # active | paused | archived
tags: [面積測定, freemium]
updated: 2026-06-17
---
```

本文の最初の行は必ず引用ブロックの要約にする：

```markdown
> 要約: ここに1〜3行で「このノートは何か」を書く。エージェントはまずここだけ読む。
```

## フォルダの意味

| フォルダ | 用途 |
|---|---|
| `00_INDEX/` | 地図（HOME と MOC）。エージェントの入口。ここ以外を最初に読まない。 |
| `10_Projects/` | 進行中の具体プロジェクト。各フォルダに `_overview.md` と `決定ログ.md`。 |
| `20_Notes/` | 原子ノート（1概念1ファイル）。MOC から参照される。 |
| `30_Resources/` | 参考資料・外部クリップ。 |
| `90_Archive/` | 終わった/不要になったもの。消さず退避（無限容量の受け皿）。 |
| `_templates/` | ノート作成用テンプレート。 |
